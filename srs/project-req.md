# Контроль доступности внешнего API и уведомление о сбое

Эта карточка описывает функцию контроля доступности целиком. Строго проверяемые (атомарные) требования, на которые она разбита: REQ-FUNC-001, REQ-FUNC-002, REQ-FUNC-003, REQ-FUNC-004 (раздел 3.2 SRS). При расхождении текстов главным считается SRS.

Связанные требования: REQ-FUNC-010 (вход, адрес почты для писем), REQ-SEC-001 (изоляция данных), REQ-SEC-003 (шифрованное хранение ключей доступа), REQ-PERF-001 (кэширование).

## Формулировка

Система должна позволять пользователю добавить внешний API (название, адрес эндпоинта, интервал проверки, необязательно ключ доступа), автоматически и регулярно проверять его доступность, показывать текущий статус на главной панели и уведомлять пользователя на экране и по электронной почте, если API стал недоступен, а также когда он снова заработал.

## Обоснование

Команды, которые используют внешние API, часто узнают о сбое поставщика только от своих клиентов. Автоматическая проверка со статусом на одном экране сокращает это время. Уведомление только после трёх неуспешных проверок подряд защищает от ложных тревог из-за кратковременных сбоев сети.

## Критерии приёмки

* **Добавление:** пользователь может добавить API, указав название, адрес эндпоинта, интервал проверки и (необязательно) ключ доступа; пустое название отклоняется с сообщением, указывающим на поле «Название»; адрес, не являющийся корректным адресом HTTP или HTTPS, отклоняется с сообщением, указывающим на поле «Адрес».
* **Интервал:** допустимый интервал — целое число минут от 1 до 60, по умолчанию 5; значения 0 и 61 отклоняются. Следующая проверка начинается через заданный интервал с отклонением не более 10 секунд.
* **Неуспешная проверка:** ответ не получен за 10 секунд либо получен HTTP-код 5xx. Ответ с кодом 2xx, 3xx или 4xx — успешная проверка.
* **Статус на панели:** для каждого API отображаются статус (работает / недоступен), время последней проверки и время ответа («нет ответа», если ответ не получен). Статус «недоступен» появляется после трёх неуспешных проверок подряд, «работает» возвращается после первой успешной. Панель обновляется без перезагрузки страницы не позднее чем через 30 секунд.
* **Уведомление о сбое:** после трёх неуспешных проверок подряд создаётся одно уведомление на экране и отправляется одно письмо, не позднее чем через одну минуту после третьей проверки; после двух неуспешных уведомления нет.
* **Без повторов:** пока API остаётся недоступным, новые уведомления об этом сбое не создаются. Если после восстановления снова наступили три неуспешные проверки подряд, это новый сбой и новое уведомление.
* **Восстановление:** после первой успешной проверки недоступного API отправляется уведомление о возобновлении работы (на экране и по почте).
* **Адресат:** письма уходят на адрес электронной почты владельца API.
* **Сбой почты:** если почтовый сервис недоступен, уведомление остаётся на экране.

## Метод верификации

Основной: Тест (TC-FUNC-001…TC-FUNC-004). Вторичный: Демонстрация, для приёмки заказчиком.

* **Тест:** проверить граничные значения интервала (0, 1, 60, 61 минута); смоделировать эндпоинт с кодом 500 и эндпоинт, не отвечающий более 10 секунд, и убедиться, что проверка неуспешна; убедиться, что после двух неуспешных проверок уведомления нет, а после третьей оно одно и статус стал «недоступен»; проверить уведомление о восстановлении, новый сбой после восстановления и поведение при недоступной почте.
* **Демонстрация:** показать на тестовом эндпоинте путь от добавления API до получения уведомления и возврата в статус «работает».

## Дополнительная информация

* **Макеты и модели:** главная панель и форма добавления API — `srs/img/mockup-dashboard.png`, `srs/img/mockup-add-api.png`; диаграммы SysML v2 — `srs/img/*.sysml` (приложения A и D SRS).
* **Зависимости:** почтовый сервис; проверяемые эндпоинты должны быть доступны из интернета; адрес для писем берётся из учётной записи пользователя (REQ-FUNC-010).
* **Время обнаружения сбоя:** примерно (3 − 1) × интервал + время проверки; при интервале 60 минут больше двух часов. Принято осознанно: интервал выбирает пользователь.
* **Открытые вопросы:** способ передачи ключа доступа (C1), считать ли 4xx сбоем (C2), судьба расходов при удалении API (C3), что именно кэшируется (C8), адреса внутренних сетей (C9). Подробности — в приложении C SRS.
* **Вне этого требования:** учёт расходов, бюджет и лимиты (REQ-FUNC-005…009), вход и безопасность (REQ-FUNC-010, REQ-SEC-001…005).

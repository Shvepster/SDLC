# Использовать Spring Boot 3 на Java 21 для серверной части

## Контекст и постановка задачи

SRS (раздел 2.3) требует, чтобы серверная часть ApiPulse была написана на Java. Серверу нужно принимать запросы браузера, аутентифицировать пользователей (REQ-FUNC-010, REQ-SEC-001 … REQ-SEC-004), по расписанию проверять внешние API (REQ-FUNC-002), отправлять письма (REQ-FUNC-004) и работать с базой данных. На проект отведено 10 недель по 25 рабочих часов в неделю, поэтому важно не писать «с нуля» то, что уже есть в готовых библиотеках.

Какой фреймворк взять за основу серверной части?

## Драйверы решения

* Обязательное ограничение: язык Java (SRS 2.3)
* Готовые средства безопасности: хеширование паролей, фильтры аутентификации (REQ-SEC-001, REQ-SEC-002, REQ-SEC-004)
* Готовые модули для базы данных, почты, планировщика и проверки входных данных
* Тестируемость (модульные и интеграционные тесты)
* Малый срок разработки и хорошая документация

## Рассмотренные варианты

* Spring Boot 3 (Java 21)
* Quarkus
* Javalin или другой лёгкий каркас с ручной сборкой компонентов

## Итог решения

Выбранный вариант: «Spring Boot 3 (Java 21)», потому что стартеры Spring (Web, Security, Data JPA, Mail, Validation) закрывают почти все технические потребности проекта, а Java 21 (LTS) даёт виртуальные потоки, удобные для сотен одновременных сетевых проверок.

### Последствия

* Хорошо, потому что безопасность, доступ к БД и почта подключаются настройкой, а не написанием кода
* Хорошо, потому что виртуальные потоки Java 21 позволяют проверять много API параллельно без сложного пула потоков
* Хорошо, потому что у Spring много документации и примеров
* Плохо, потому что Spring использует много «магии» (аннотации, автоконфигурация), которую нужно понимать при отладке
* Плохо, потому что приложение потребляет больше памяти (порядка 300–500 МБ), чем у Quarkus

### Подтверждение

* Инспекция `pom.xml`: Java 21, Spring Boot 3.x
* Архитектурный тест (ArchUnit): пакет `web` не зависит от пакета `infrastructure` (SDD, представление 006)

## Плюсы и минусы вариантов

### Spring Boot 3 (Java 21)

* Хорошо, потому что есть готовые решения для всех задач проекта
* Хорошо, потому что соответствует ограничению «Java»
* Нейтрально, потому что стартовое время и память выше, чем у более лёгких каркасов
* Плохо, потому что много неявной конфигурации

### Quarkus

* Хорошо, потому что быстрый старт и малое потребление памяти
* Плохо, потому что меньше учебных материалов и примеров по безопасности с JWT
* Плохо, потому что выигрыш по памяти проекту не нужен (один сервер)

### Javalin или лёгкий каркас

* Хорошо, потому что максимум контроля и минимум «магии»
* Плохо, потому что безопасность, миграции и работу с почтой пришлось бы собирать вручную: это десятки часов сверх бюджета
* Плохо, потому что больше риска ошибок именно в безопасном коде

## Дополнительная информация

Затронутые требования SRS: REQ-FUNC-010, REQ-SEC-001 … REQ-SEC-004, REQ-FUNC-002, REQ-FUNC-004. Представления SDD: 002-composition, 006-dependency. Связанные решения: ADR-0003, ADR-0005.
